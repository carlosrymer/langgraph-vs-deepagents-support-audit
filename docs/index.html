LangGraph vs Deep Agents: what happens when the tool output gets big

I gave the same model the same tools and prompt, and swapped only the scaffold. When the tool outputs got big, default Deep Agents answered correctly. A plain LangGraph loop answered , and so did Deep Agents with offloading switched off (). The whole gap comes from one middleware setting.

The caveat: the wall the other two arms hit was my OpenAI account's 200k-token per-request limit, not the model's 400k context window. Below that wall, accuracy differences are within noise, and Deep Agents' advantage is cost: vs per run at the L size. Offloading also brings its own failure mode: when it searched the offloaded file with grep it passed , and when it read only a window of the file it passed .

Accuracy as the exports grow

Every ticket's transcript gets longer as the size dial goes up, but the ticket fields don't change, so every gold answer is identical at every size. Any drop in accuracy comes from context pressure alone. Whiskers show 95% Wilson intervals.

Why: the largest request each scaffold tried to send

A plain loop keeps every export in context, so its biggest request grows with the size dial. Deep Agents writes any tool result of 80,000 characters or more to a virtual file and hands the model a pointer and a preview. The model then greps the file. Each point is the largest request any run in that cell tried to send. For rejected requests, it's the size OpenAI quoted back in the 429, which includes an 8k output reservation.
